## 1. 背景与目标

课表 `docs/career-plan/2026-07-java-backend-interview-prep.md` 覆盖 M1–M10 共 10 个模块，每个模块列出了 8–10 道面试高频题，但尚未沉淀为结构化知识文档。本次从 **M1 JVM** 试点，跑通文档结构、详略分级、课表联动的流程，后续模块按相同节奏推进。

**目标**：产出一份面试导向、结构化、可被课表逐学时引用的 JVM 知识点文档。

**深度定位**：面试能讲清（定义 → 原理图 → 面试话术 → 常见追问），源码只附关键片段。

## 5. 详略分级与写作模板

### 详略分级

| 级别 | 适用对象 | 篇幅 | 模板 |
|---|---|---|---|
| **详写** | 高频题核心知识点（如堆、GC 算法、双亲委派、CMS/G1） | 400–800 字 | 完整模板 |
| **略写** | 辅助知识点（如 PC、本地方法栈、直接内存） | 100–200 字 | 简化模板 |
| **索引** | 仅涉猎的深度知识（如 ZGC 染色指针、SATB 源码） | 30–50 字 | 仅链接 |

## 6. 质量要求与验收标准

### 写作要求

1. **准确性**：每个定义/机制须有可追溯的权威来源链接，不凭记忆编造
2. **结构化**：每节严格套用模板（定义→结构→关键点→话术→追问→来源）
3. **图表**：堆分代、GC 阶段、类加载流程等核心图示用 Mermaid 或 ASCII，确保 GitHub 可渲染
4. **话术可口述**：面试话术写成连贯段落而非 bullet 堆砌，能直接对着说
5. **追问覆盖**：每章至少列 3 个面试官常见追问，附简短应答方向

### 验收标准

| 检查项 | 标准 |
|---|---|
| 10 道高频题全覆盖 | 每题在文档中有对应小节，速查索引能定位 |
| 课表 4 学时可引用 | 每章标题 anchor 在 GitHub 上可跳转 |
| 来源可追溯 | 详写知识点均有至少 1 个权威外链 |
| 图表可渲染 | Mermaid/ASCII 在 GitHub Markdown 预览不破 |
| 篇幅 | 约 10000–12000 字，详略分明 |
| 无占位符 | 无 TBD/TODO/待补充 |
